# MASTER TASK — WorldOS 全站产品级黑盒逆向调查

目标网站：

https://worldos.cc

---

# 0. 最终目标

我要开发一个属于我们自己的、全新品牌的 AI 世界模拟平台。

WorldOS 是核心参考产品。

我的目标不是：

* 做一个外观类似的网站
* 模仿几个页面
* 做一个简单 AI Chat
* 做一个只有 World + Character 的简化版本
* 根据首页介绍猜测它的功能
* 做一个所谓 MVP 后就停止

我的目标是：

> **完整理解 WorldOS 当前整个产品是如何工作的，并把它所有公开可使用的产品能力、用户流程、玩法、系统、编辑器、内容组织方式和交互机制整理成一套足够详细、可以重新实现的产品规格。**

之后，我们将在这个研究结果基础上设计一个：

> **拥有我们自己的品牌、视觉、代码和内容，但在产品能力和使用体验上与 WorldOS 达到完整功能对等的新平台。**

---

# 1. 最终验收标准

这次研究是否成功，不看文档写得多不多。

唯一真正的标准是：

> 如果未来同时打开 WorldOS 和我们的产品，对两边执行相同的用户任务，我们是否已经掌握足够的信息，让自己的产品能够提供基本相同的功能、流程、交互能力和模拟体验？

例如：

WorldOS 可以：

创建某种东西
→ 我们也应该知道如何设计对应能力。

WorldOS 可以：

修改某项东西
→ 我们也应该存在对应流程。

WorldOS 点击某按钮会出现某种状态变化
→ 我们必须知道这个状态变化。

WorldOS 一个 Simulation 运行 20 个 Turn 后发生某种行为
→ 我们必须研究并记录。

WorldOS 某个 App 与其他 App 联动
→ 我们必须调查这种联动。

WorldOS 某种对象可以：

创建
浏览
搜索
安装
编辑
复制
Remix
运行
保存
分享
发布
删除
恢复

那么这些生命周期行为都必须调查。

最终目标是：

## Functional Parity

功能对应。

## Workflow Parity

完成同一任务所需的流程对应。

## Behavioral Parity

执行同一操作以后产生的系统行为对应。

## Simulation Parity

世界运行、角色反应、状态变化、App 联动等核心体验对应。

## Creator Parity

World / Character / App / Map 等创作者能力对应。

## Persistence Parity

保存、恢复、历史、版本、Rewind 等行为对应。

## Platform Parity

探索、搜索、社区、个人内容、发布、商业化等外围平台能力对应。

# 4. 调查方式

使用浏览器真实操作 WorldOS。

不要只使用：

* 首页文字
* Google 搜索结果
* SEO 页面
* FAQ
* 网站介绍

这些只能作为辅助资料。

真正的重要信息来自：

> 实际操作。

需要：

* 打开页面
* 点击按钮
* 展开菜单
* 创建测试内容
* 开始 Simulation
* 连续运行 Turn
* 修改配置
* 保存
* 返回
* 重新进入
* Remix
* 安装 App
* 切换 App
* 测试 Character
* 测试 Map
* 测试 Creator
* 测试各种状态

如果正常操作需要登录，可以使用已经合法登录的测试账户。

不得：

* 绕过身份验证
* 绕过权限
* 利用漏洞
* 获取其他用户私人数据
* 获取服务器源代码
* 窃取密钥
* 复制其非公开代码

这是：

> 产品行为黑盒研究。

而不是服务器攻击或源码复制。


如果 WorldOS 能完成，而我们的产品规格里根本没有对应能力：

# 研究不完整。

如果两边完成同一个任务的核心体验完全不同：

# Parity 不达标。

如果我们只能模拟页面，但无法模拟 WorldOS 的世界状态、人物连续性、Turn、Apps 联动：

# 项目失败。

我们的最终目标是：

> **一个熟悉 WorldOS 的用户进入我们的产品以后，即使品牌和视觉完全不同，也应该很快发现：他以前能做的事情，这里基本都能做；以前知道怎样玩的，这里也知道怎样玩。**

这就是最终的：

# PRODUCT EXPERIENCE PARITY

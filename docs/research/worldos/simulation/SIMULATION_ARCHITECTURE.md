# Simulation Architecture

Status: `PARTIAL / evidence-backed`

Simulation is an independent persistent run bound to an applied WorldVersion. It owns a Turn timeline, runtime App data, Story, Character Chats/relationships, Map state/current location, Wallet/transactions, Inventory, Stats, Quests, World State, Memory, one-time `playerSetup` identity and checkpoints. World/App configuration is a separate layer: it can survive Rewind and be incrementally updated by WorldVersion. EVD-0232 further proves visible Character Memory is Simulation/checkpoint-scoped: a source can generate and edit a summary without mutating an older checkpoint's empty Memory state. Automatic summaries are batched and can trail the latest transcript; committed manual edits persist and enter the next model context. EVD-0236 separates `playerSetup` from visible Memory: the exact Persona-derived object exists while the Memory panel remains empty, yet the next model Turn uses it. A current-state checkpoint copies the exact identity and consumed lock; viewing historical Turn 1 overlays the same current identity; native-confirm Turn2→1 Restore removes the later Story but preserves identity/lock through reload. `playerSetup` is therefore Simulation metadata outside the rewindable Turn snapshot in this sample. EVD-0249 adds a controlled contrast: a no-identity-field Map World used later manual identity verbatim, but a World with `/new` identity field `Alice` let that World field override it in Main Input/Chat. The existence and persistence layer are verified, but AI prompt composition priority between World setup variables and Simulation `playerSetup` is World-dependent or defective.

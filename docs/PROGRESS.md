## 现在的样子

产品计划的 5 步都做完了，每步都经过 Sonnet 审查、真实模型实测，CI 全绿。

1. **能玩起来**：手动和 AI 生成世界（8 个问题，或复制提示词给别的 AI、粘贴回来）、写作规则栏；以任何角色或导演游玩；
   故事流式显示；每回合 2–3 条建议；变化自动记录、用人话列出，失败可“重新记录”；退回、其他走向、分支、多存档；
   设置：人称、主动程度、篇幅、文风、深度思考、看全部秘密，以及存档自己的“重要事实”。
2. **秘密**：AI 开局埋 2–3 个，之后每 4 回合补；发现册；建议和人物只知道自己见过、听过的事。
3. **活的世界**：在场和离场（只把同一地点的人写全）；主角的位置每回合由回复里的 "where" 定；人物登场、退场；
   每 5 回合“与此同时”，不在场的人按自己的打算走一步；时间跳跃（“三天后”）先让场外的人过完这段时间；命运骰子。
4. **换角度和成果**：上回说到、角色访谈、换个视角、关系图、小说化（每 10 回合一章，导出 .txt）。
5. **离线发展**：隔一天以上回来，世界先过 2–7 天；可选主角不动或一起过。

## 关键做法（改之前先看）

- **一回合一次请求**：模型回一个 JSON `{story, where, changes, hooks}`，故事在前、边收边显示，漏了字段再补一次请求。
  讲故事不思考（第一个字 2–4 秒、整回合 9–20 秒）；建世界、整理记忆用思考。
- **默认模型** `ModelScope/deepseek-ai/DeepSeek-V4.1-Flash-1017`（旧名字已经调不通）。服务商常无故 400、524、断流，
  所有请求统一重试；流里报错当失败。
- **长期记忆**：每 10 回合在后台写一段时间线（只增不改，太长时 5 段合 1 段）和记忆（最多 20 条、写“现在怎么样”、
  按优先级取舍）；发给模型的超过 64K token 时撤掉时间线讲过的老原文，留最近 30 回合。玩家永远不用等。
- **设置优先于世界规则**：篇幅、人称、主动程度、文风以设置为准，作者规则管其余。“AI 味”是世界规则造成的（要求
  各有口头禅、不解释动机），是世界的特色，不改世界，也不靠“少用逗号”这类规则硬压（试过无效，已撤）。
- **不替玩家做事**：玩家没写的话和决定一概不写，有人问就停在问题上；骰子结果只写这次尝试。
- **骰子**：模型只判断风险和难度并写好“成功 / 失败意味着什么”（温度 0），服务器掷 d20，结果当定死的事实给故事。
- **场外的改动**只能改位置、现状、关系，不能让人退场、不能进玩家的场景；点了名或被故事改过的人按故事来。

## 网页改版（2026-10-20 起）

用户觉得页面像测试版。按设计流程：参考获奖网站和同类产品 → 方案 → Sonnet 两轮审查 → 用户选了“融合方案”（A 书房的阅读 +
B 夜读的夜色和关键时刻 + C 留白的克制控件）。样稿：claude.ai 上的“Simulora 网页改版样稿”。定下的规则：
- 字体用本机思源宋体 / 思源黑体，不联网加载；正文 17px、行距 1.85、首行缩进、最宽 660px。日夜两套颜色（跟随系统，可改）。
- 主按钮墨色；朱砂只在左上角标志；对话蓝、成功绿、有代价黄、失败红、秘密紫各占一色，都配图标和文字。
- 宽屏面板常驻右侧（世界 / 前情 / 设置 / 访谈），1280 以下变抽屉，手机变底部抽屉；输入框贴在阅读区底部。
- 用户试用后：游玩页顶栏只留一个“面板”按钮（各种屏幕一样），世界 / 前情 / 设置 / 小说都在面板里；顶栏以后放首页、
  个人、探索这类全站页面。
- 主页“继续上次”+ 世界卡（按最近游玩），点世界进世界详情选存档；新存档自动叫“第 N 局”；删除用应用自己的确认框。
- 过去的回合在前情面板里展开读，可退回、分支、换视角；“上一回合”就是打开这里。

第一步（框架，照样稿）已完成：服务器的世界列表带上每个存档的回合数、最后一句、发现进度；前端重写成 ui / Home / World /
Play / Turn / Panels / Novel / Graph，样式整份重写。用无界面 Chrome 逐页截图核对了日夜、宽屏、平板、手机。

## 秘密跟着故事走（2026-10-20）

## 公开内测 第 2 阶段（2026-10-21 起，进行中）

邀请制内测，全球可用。已定：作者自己的服务器 + Cloudflare Tunnel（网页和接口同一地址，服务器只听 127.0.0.1），
数据库沿用服务器上的 SQLite，先不做备份；邮箱验证码登录，发信用 Gmail 小号的应用专用密码（`.smtp.txt`，不提交）。
- 用户归属：世界记主人（`user_id`），存档、回合跟着世界；所有按编号取世界和存档的接口都校验归属。
- 账号（`--public` 才有）：邀请码注册（管理员邮箱不用）、6 位验证码登录、会话 30 天（`__Host-` Cookie）。
  邮箱只收常见邮箱；同一信箱的写法（大小写、Gmail 的点、支持别名的邮箱的 +后缀）算一个账号，验证码发到这个信箱；
  QQ、163 等不支持别名的邮箱带 + 直接拒绝。问验证码对有没有账号一视同仁；每个“邮箱 + IP”各有自己的验证码。
  限额：重发 60 秒、每邮箱每 IP 每天 5 封、每邮箱每天 15 封、每 IP 每小时 10 封、全站每天 300 封。
  删除账号先删世界再删账号，启动时清掉没有主人的世界。隐私说明页。
- 线上模式：只认 SITE_URL 的地址，修改请求必须来自本站页面；本机模式拒绝一切经代理来的请求；设了 SITE_URL 必须 `--public`。
- 点数（线上）：每人每天 30 点（北京时间 0 点），管理员不限。回合 1；深度思考或跳时间 2；AI 搭世界 3；访谈、视角、上回说到、
  小说一章 1（读已有的不扣）；换一批建议、重新记录 0.5（新开局自动的第一批不扣）。没产出就退。每人同时一个回合或搭世界，
  最多 10 个世界、每个 20 个存档。
- 闸门（`server/gate.ts`）：每次发给服务商的请求都排队：同时 3 个、每分钟 20 个、429 全站停 30 秒；玩家先于后台整理
  （后台等 90 秒后提前）；放弃的等待（骰子、与此同时超时）离开队伍不花额度；当天请求数存库，线上上限 1800，
  到 85% 不开新动作、90% 后台停。数字都能用环境变量改。
- 防 524：回合流每 15 秒心跳；其他接口 10 秒没回完就先发头、再定时发空格，结果最后写，失败放在 JSON 里。
- 上线（2026-10-21）：https://simu.hyzvo.com 。作者的服务器（Ubuntu 24.04，另有 nginx、docker 等服务，都没动），
  root 运行；Node 24 在 `/opt/simulora-node`（系统 Node 22 不动），代码在 `/opt/simulora`，数据在 `/var/lib/simulora`，
  配置 `/etc/simulora.env`，服务 `simulora`（systemd，只听 127.0.0.1:5180）；Cloudflare Tunnel `simulora`，配置
  `/etc/cloudflared/config.yml`。部署：本机打包 server、shared、web/dist 传上去，重启服务。实测经 Tunnel 150 秒的
  流式和普通回复都不断；服务器能连 Gmail 465。部署用本机的专用密钥登录（`~/.ssh/simulora_deploy`）。
- 视觉（2026-10-21）：6 个示例世界的封面和新玩家首页的主图（GPT 生成，原图在不提交的 `art/`，网页用压缩的 JPEG）；
  从示例开的存档也用示例封面，玩家自建的世界仍是颜色加首字。图标换成朱红山水石灯印章（标签页、手机桌面、页面左上角）。
- 管理员页面 `#/admin`（只有管理员能打开，别人得到 404）：今天的模型请求和验证码请求、生成和作废邀请码（复制注册链接）、
  每个玩家今天的用量、世界数、单独设每日点数、停用和恢复账号（停用立即登出）、服务器最近 50 条警告（内存里，重启清空）。
- 下一步：部署脚本；未登录也能逛首页和示例。

## 已知问题（都不挡游玩）


- 模型偶尔笔误：“沙菲克”写成“萨菲克”、夹一个英文词。

- 浏览器每次加载带全部故事原文（1000 回合约 1.5 MB），以后分页。
- 回合进行中删除存档会留下一个孤立节点。

# Simulora 最终产品目标与方向校验

**来源：** 用户于 `2026-09-15` 对最终体验目标的明确补充，并要求长期记录。
**性质：** 后续工程与 Reality validation 的方向约束，不是新阶段实施授权，
不改写冻结 Product / System / Experience，不把最终愿景全部塞进当前 MVP。

## 最终体验目标

Simulora 不是普通 AI chat，也不只是状态管理系统。用户应真正拥有一个
可以长期继续的 AI 世界：有世界规则、角色、地点、关系、事件和因果连续性，
不是只拥有一段对话或一个不断被替换的事实字段。

用户希望同时保留两种体验视角：

- **世界导演 / 控制者：** 可以塑造世界的整体结构，并在明确授权范围内影响
  世界发展；不是只能向某一个角色发消息。
- **进入世界扮演角色：** 用户只控制自己，其他角色保有独立动机、知识、
  判断、分歧和拒绝能力，世界由 AI 根据连续状态作出自然回应；不替用户
  发言、作决定或承担受保护的承诺。

例如，喜欢魔法奇幻的用户最终应能创建一个完整的魔法世界，并长期玩下去。
这是世界深度与长期可玩性的目标，不是这轮立即实现全部魔法系统的要求。
WorldOS 只用于说明 AI World 的产品类别和体验期待，不作为复制其 UI、
素材、代码或具体机制的授权，也不恢复已停止的全站黑盒研究。

## 不得误解的边界

- 两种视角不是把 AI Initiative 与 World Structure 压成一个 mode。
  导演、参与者、Character、Continuity 的 authority 仍必须明确分离。
- 塑造未来 World Revision 不等于当前 Continuity 自动采用；导演视角
  不授予模型任意改写当前事实、绕过确认或越过 ownership / consent 的权限。
- 长期运行首先意味着世界可持续、可返回、可继续，有可信的历史与当前状态；
  不自动授权离线推进、无人值守无限生成、跨 session 自动 Commit 或新增后台成本。
- AI 的自然运行必须落在冻结 participation 与 authority 契约内。
  模型输出仍不等于已经发生的事实；受保护 / L3 操作仍需 exact confirmation。
- 已批准的阶段性安全能力应保留；但它们不能替代“世界真的能活起来”的产品验证。
  新的产品冲突或缺失需显式提出决策，不通过实现捷径悄悄改契约。

## 当前已确认的收窄风险

[实际 Spike](PRODUCT_REALITY_SPIKE_REPORT.md) 暴露了 first-fact / first-Character
context 与单一 canonical fact rewrite 的运行时天花板。普通对话、拒绝或
世界发展被挤进同一个事实更新，会使产品退化为“单事实修改器”。

[RE-1](RETURN_CURRENT_SITUATION_REPAIR_REPORT.md) 修复当前 lead 的来源，
**没有证明完整场景、多角色或世界模拟成立**。第一条共享事实是临时 factual
lead，不是最终 World 的定义。短暂而流畅的角色回应也不证明长期世界可玩。
这些边界必须在未来状态交接中持续保留，不能因测试绿了就被默认为最终范围。

## 后续方向校验

| 后续工作                 | 必须校验的方向                                                                                     | 不能被当作成功的替代品                                                    |
| ------------------------ | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| RE-2 context / Character | 世界规则、当前场景、授权历史和实际选择的不同角色能进入运行链路；角色知识与动机不同                 | 永远选择第一角色，只扩充提示词或把全部事实泄露给所有角色                  |
| RE-3 routine effects     | 逐步表达有意义且有因果的世界发展；无世界变化的回应不必伪装为事实改写；影响由服务端封闭规则判断     | 任意 JSON mutation、每句话改一个 canonical fact，或为减轻负担删除 L3 确认 |
| Reality validation       | 验证连续多次行动、返回、角色分歧、世界变化和用户 agency；结合人类体验与真实模型 evidence           | 只证明数据库 invariant，或只评价一段聊天写得好不好                        |
| 未来 IP-7 World Studio   | playable-first；创作结构能实质影响未来世界体验，保持 proposal / adoption / current Continuity 边界 | 把 Studio 做成表单 / dashboard，或宣称草稿已经改变当前世界                |
| 长期 qualification       | 验证时间跨度、多个 session、历史 / 当前 truth、可继续性与恢复后的因果连贯                          | 短 Spike 自动升级为长期记忆、完整 AI 世界或发布资格                       |

这些是最终方向与分阶段的验证问题，不要求本轮 RE-1 或每一个早期 slice
立即实现全部能力。后续计划 / Gate 必须区分：已验证的阶段能力、明确的
实现天花板、尚待实验的问题和最终愿景缺口。

如果路线开始固化为单事实修改器、普通聊天，或者只有管理界面而没有可玩世界，
主 Agent 必须主动指出具体实现证据、体验后果和最小后续决策，不能默默接受收窄。
RE-1 通过后，用户已授权 RE-2 的 bounded context / Character 实施；RE-3 与新一轮
full Reality 执行范围仍待批准。用户随后授权最多 8 次 RE-2 context-only comparison，
现 [1/8 派发后因供应商 HTTP 429 暂停](RE-2-CONTEXT-REALITY-CHECK.md)，无模型输出；
这不证明世界质量、不授权 RE-3/full RE-4。最终目标不自动批准后续阶段；**IP-7 尚未开始**。
